# ADR 0133: 製品文書の自律所有と現役面の縮約

- 状態: Accepted
- 日付: 2026-08-30
- 決定者: オーナー／dotagents
- 先行裁定: ADR 0126、ADR 0132

## 背景

ADR 0126は「工場横断はdotagents、製品固有は各製品repo」という所有境界を定めた。しかし、その後も製品の診断、導入、状態、運用判断をdotagents側の文書へ再掲できる構造が残った。ADR 0132は現行値の重複を機械的に減らしたが、対象を意味重複や文書の置き場所まで広げていなかった。このため、完了済み文書が現役面に残り、同じ説明が複数の入口に蓄積し、製品を単独で切り出した時に必要な制御文書がdotagents側へ取り残される。

## 決定

1. **dotagentsは各製品を統括するが、制御しない。** dotagentsが所有するのは製品集合、host適用、相互接続、互換性、工場投影、横断受入である。製品の導入、設定、状態、schema、migration、診断、運用、release判断は各製品repoが所有する。
2. 各製品はdotagentsが存在しなくても、READMEと製品内文書だけで導入、利用、診断、復旧、更新、release判断ができなければならない。dotagentsは製品文書を代替せず、製品が公開する入口を参照する。
3. 現在の判断や操作に不要な完了済みplan、handoff、migration記録、旧設計、旧版案内は`archive/`配下へ移す。immutableな証拠参照を壊す文書は移動せず、`evidence`または`history`として現役の読書入口から外す。
4. 同じ意味の現役文書は一つへ統合する。統合後の旧入口は、消費者が存在しない時は削除し、互換入口が必要な時だけ後続正典への短い導線にする。
5. ADR 0132の現行値生成は、製品集合、wire、endpointなどdotagentsが所有する**統合上の事実だけ**へ限定する。製品内部の制御事実を中央正本へ吸収しない。
6. 文書分類はlifecycleだけでなく所有者と役割を検査する。dotagentsの現役文書に製品固有の制御を新たに置く変更と、製品repoから単独運用入口を失わせる変更を受入れない。

## 非目標

- 製品source repoの移動、改名、統合は行わない。
- 製品runtimeの責務や公開APIを、文書整理を理由に変更しない。
- 履歴の内容を現在基準で書き換えない。
- 第三者製品の内部文書や実装をdotagentsへ複製しない。

## 実行単位

### 1. 基準線と全文書目録

全対象repoの同期状態、dirty、現役入口、履歴、重複候補、参照元を実測し、変更前の受入基準を固定する。

### 2. 所有境界と意味重複の監査

dotagentsにある製品固有制御を製品別に仕分け、同義文書の統合先と、履歴へ移す文書を決める。grepだけで削除可否を判断しない。

### 3. dotagents現役面の縮約

古い文書をarchiveへ移し、同義説明を統合し、製品契約台帳を横断統合契約へ縮約する。現役面は正典への短い地図として保つ。

### 4. 製品repoへの所有還流

製品固有の導入、設定、状態、診断、復旧、更新、release判断を各製品repoの既存正典へ統合する。新しい重複文書は増やさない。

### 5. 自律性と文書境界の機械検証

各製品が単独で必要入口を保持すること、dotagentsが統合事実だけを保持すること、現役面へ履歴が再流入しないことをfocused testで検証する。

### 6. 全体受入と知識還流

対象repoごとの関連test、横断整合、clean、commit、push、remote CIを確認し、今回の所有判断と移動一覧を履歴証拠へ固定する。

## レーン裁定

複数repoの書込みを調整し、製品ごとの受入から工場横断受入までが連鎖し、所有境界の検証可能な証拠を要するため統括レーンとする。計画済み中断と人だけが下せる裁定はない。

## 帰結

dotagentsを外しても各製品の制御は失われない。一方、dotagentsを読む時は工場全体の接続と互換性だけを短く把握でき、完了済み文書や重複説明を無意識に読むtoken消費を抑えられる。
