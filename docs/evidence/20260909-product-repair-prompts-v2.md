# 製品ごとの改修依頼文（実端末試験の手順を明記した改訂版）

2026-09-09の調査・実装状況を引き継ぐための依頼文。製品の恒久的な導入・公開手順の正本は、それぞれの製品repoにある。

各節のコード枠だけを、その製品フォルダで起動したAIへ貼る。共通の前置きを別に貼る必要はない。
実装と隔離試験は並行で進められる。同じ端末の共有AI設定へ書き込む本番導入は、製品ごとに順番に行う。
各製品の公開版・正規入口・検証結果が揃った後、最後のdotagents向け依頼文を使う。

修理対象はCaveat、gpt-connector、codex-sidecar、AIShell、Lattice、Peertable。
ServerManager/BugHubは中断していた通知修理を別に引き継ぐ。Aitermは導入改修が公開済みなので、残る実機確認を中心にする。
Throughline、unai、Spotterは、今回の調査で製品本体の新規修理が必要とは確定していない。工場の呼出し方の修理は最後のdotagentsへ残す。
