# Knowledge return

所有: dotagents所有・全project向けL2正典。

RAG還流六手順・raw/コンパイル分離・INDEX規約・月次衛生の詳細を扱う。

## 調査と出力の還流

- **調査を無駄にしない。** 調べた／検証した外部仕様・文献は、その都度 MarkItDown で Markdown 化し `rag/` に保管して再利用可能にする（取得系の罠は caveat が正）。**raw/（一次ソース verbatim）とコンパイル記事（要約・[[リンク]]・自前実測）を分ける**。各ファイルに**出典・取得日・確度**、`rag/INDEX.md` に1行追記。`rag/` が無ければ作る。
- **出力も還流させる**: 良い回答・監査ダイジェスト・図解は使い捨てず rag/ / docs/ に戻して複利で育てる。

## 保存と衛生の手順

1. 外部仕様・文献の一次ソースは`rag/<topic>/raw/`へ保存する。取得にはMarkItDown等の変換器を使い、verbatimな内容を保つ。
2. LLMが一次ソースを要約し、関連する概念へのリンクと自前の実測を加えたコンパイル記事を一次ソースとは別に作る。wiki（コンパイル記事群）の保守はLLMの仕事。
3. 各ファイルに出典・取得日・確度を記し、`rag/INDEX.md`へ内容を特定できる1行の台帳を追記する。
4. 月次でrag/のLint（リンク切れ・INDEX欠落・確度未記載の検出）と端末メモリの棚卸しを同じ枠で行う。
5. 保存対象は再利用価値のある知識と出力に絞り、何を入れないかを判断して知識棚の品質を保つ。
6. 窓は流行が去れば替えられるが、器に真実を入れると人質になる。Obsidianは`.obsidian/`を端末固有としてgitignoreし、Markdown＋gitを読む窓としてだけ採用できる。NotebookLMは主脳にはせず、一方通行の人間用窓に限る。プラグインはネイティブ機能で上位互換できるなら新規導入しない。

思想の出自はdotagents憲章原則10。
