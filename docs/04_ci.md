# 04_ci — focused gateと最終通し試験

<!-- 前提: PLAN.md 原則1②。必要性を実証した最終確認CIの設計は最上位知能の使い所。具体モデルは docs/02_models.md で解決する。 -->

dotagents は同期ハブであり、壊れた `install.sh` や `bin` スクリプトが全端末へ配布される外部境界を持つ。変更中の動作確認は対象のfocused targetで行い、すべての関連targetがgreenになった後の最終通し試験としてだけ **`make ci`** を1回実行する（[01_project-layout.md](01_project-layout.md) 必須要件「テスト＋CI」）。`make ci`で失敗した場合は失敗機能を切り分け、最小再現とfocused targetで原因特定・修正確認を終えてから、最終確認として1回だけ再実行する。`make lint` は静的lintとhook smokeをまとめた関連gateである。

## ローカルで回す（正典）

```sh
npm ci --ignore-scripts # lock固定の文書parser依存を導入
make ci         # 最終確認: 全focused/related targetがgreenになった後に1回
make lint       # shell + python + markdown + 共通憲法 + skill/hook smoke
make lint-sh    # shellcheck: install.sh + bin/*.sh + tests/**/*.sh
make lint-js    # node --check: bin/*.mjs + lib/orchestrate/*.mjs
make lint-md    # markdownlint: 生きた正典の md
make lint-constitution # 共通憲法＋host deltaと生成物の完全一致
make lint-current-docs # 全document分類＋現行状態生成物＋手書き現行値
make lint-skills # Codex skill の静的契約
make lint-hooks # Claude / Codex hook の空打ち smoke
make test-constitution # generatorの冪等性・drift拒否・入力契約
make test-current-docs # document registryの分類・生成・drift拒否
make test-ci-plan # CI変更分類と最終合否のfail-closed契約
make test-install # 隔離 HOME のinstall/configとMac／Linux server／Linux workstation一撃展開（Codex CLI 必須）
make test-update  # cron 最小 PATH から NVM 配下の npm を解決
make test-oracle  # Oracle互換rollback wrapperのNode/entry/Chrome入口をOS非依存で検証（通常入口ではない）
make test-factory-reporter # factory reporter のprivacy/outbox/retry契約
make test-orchestrate # Control Record / executor contract の動的契約
```

ビルド工程は持たない。clean checkoutでは`npm ci --ignore-scripts`でlock固定の検査依存を導入してからgateを実行する。`install.sh`単体の構文確認は`bash -n install.sh`で行う。構成entryを変更した後のinstall再実行・symlink先確認・新規Claude/Codex sessionでの一覧確認はREADME「他端末セットアップ・ランブック」の受入手順に従う。

- 依存: **GNU Make**・**shellcheck**（`brew install shellcheck`）・**ripgrep (`rg`)**（skill smoke の検索入口）・**Node.js 24以上／npm**（`package-lock.json`固定のMarkdown／HTML parserと、npx固定版`markdownlint-cli2@0.23.0`）・**python3**・**Codex CLI 0.144.1**（`make ci` / `make test-install` が実 parser として使う。CI は `@openai/codex@0.144.1` を明示導入）。Windows native一撃入口は不足時にwingetの固定package IDからこれらとGit for Windows同梱OpenSSHを導入するが、WSL2・Docker・仮想化は導入も検証もしない。Windows上のshell testはGit for Windowsのnative `bash.exe`で実行する。
- 合格＝`make ci` の全ゲート exit 0・指摘 0。`make test-orchestrate`はCI必須であり、shell・mdに加えてControl Record / executor contractの動的契約を検証する。さらに全documentの分類、構造化正本から生成する工場現行状態、current文書の手書き現行値拒否、`shared/constitution.md`＋host deltaとClaude／Codex／Grok／Cursor生成物の完全一致、Lattice工程表SessionStart hookのCLI不在／正規status／未生成／異常系、隔離HOMEでのinstall/config applyとtransaction rollback、Mac／Linux server／Linux workstation一撃展開のhost固有配線とfresh delivery、cron最小PATHからのNode/npm解決、Oracle互換wrapperのOS非依存なrollback入口、factory reporterのprivacy/outbox/retry契約を検証する。Windows native一撃展開とTask Schedulerは`make test-factory-reporter`のPowerShell source契約・scheduler fixtureで実hostへ登録せず検証し、source契約は`wsl.exe`呼出しを拒否するとともに、main-server専用鍵・pinned host key・alias／直IP config・登録workflow・複数再接続を要求する。通常のChatGPT入口はgpt-connector正本に従う。

## shellcheck（shell）

- 対象: `install.sh`、`bin/*.sh`、`tests/**/*.sh`。既存 smoke の `A && B || C` に限る SC2015 は、テスト自身が fail 状態を集計して最後に終了する意図的な形のため除外し、他は既定ルールのまま維持する。
- shell は本数が少なく密度も低いので既定ルールで green を維持できる＝厳格側に置く。

## markdownlint（docs）— 構造検査

- 設定: [`.markdownlint-cli2.jsonc`](../.markdownlint-cli2.jsonc)（リポ直下）。対象は**生きた正典と配布 skill**＝ルート `CLAUDE.md`/`README.md`・`claude/CLAUDE.md`・`claude/skills/**/*.md`・`codex/AGENTS.md`・`codex/skills/**/*.md`・`grok/AGENTS.md`・`grok/AGENTS.delta.md`・`cursor/AGENTS.md`・`cursor/AGENTS.delta.md`・`cursor/rules/factory.mdc`・`shared/**/*.md`・`docs/**/*.md`。`docs/archive/**`（凍結）・`docs/evidence/**`（完了task証跡。Lattice evidence記述子がgit_blob_oid/content_digestで内容を束縛するため、後から編集すると証跡と食い違う）・`node_modules/**` は除外。
- 方針: **正しく描画される既存の知識文書と戦わない**。純スタイル系の4ルールだけ無効化し、構造系（見出し階層・見出し前後空行・末尾改行・ハードタブ・空リンク 等 ~40 ルール）は既定のまま残す＝将来の編集の破綻は捕まえる。
- **無効化した4ルールと根拠**（勝手に有効へ戻さない・戻すなら既存文書の一括修正とセットで裁定する）:

| ルール | 内容 | 無効化の理由 |
|---|---|---|
| MD013 | line-length（80桁） | 日本語散文＋広い表に固定桁は不適。折り返しは可読性を下げる |
| MD060 | table-column-style | 表パイプ整列の見た目のみ。意味に無関係 |
| MD040 | fenced-code-language | ASCII ツリー図・テキスト断片に言語指定は無意味 |
| MD031 | blanks-around-fences | リスト内フェンス（GitHub で正常描画）にだけ発火する摩擦 |

## 共通憲法の生成一致

- 人が編集する共通条文の唯一の正本は`shared/constitution.md`、host固有条文は`claude/CLAUDE.delta.md`と`codex/AGENTS.delta.md`と`grok/AGENTS.delta.md`と`cursor/AGENTS.delta.md`に置く。
- `node bin/render-global-constitution.mjs --write`が`claude/CLAUDE.md`と`codex/AGENTS.md`と`grok/AGENTS.md`と`cursor/AGENTS.md`と`cursor/rules/factory.mdc`を決定論的に生成する。Cursor runtimeへsymlinkするのは`factory.mdc`だけ。生成物はruntimeへ直接symlinkされるため、外部Markdownをモデル自身に読ませるfallbackを使わない。
- `bin/verify-constitution-parity.sh`はgeneratorの`--check`を呼び、生成物が正本＋deltaと完全一致しなければ非0終了する。生成物の直接編集や再生成漏れは`make lint`で拒否する。
- `node --test tests/constitution/generation.test.mjs`が冪等生成、drift拒否、不正引数拒否を動的に検証する。

## 現行文書の分類と生成一致

- [document registry](document-registry.json)は全Markdown／MDCを`generated`／`current`／`contract`／`history`／`evidence`へ分類し、各ruleの所有roleも必須にする。`current`は明示したpathとroleだけのclosed setであり、未分類の新規文書を拒否する。製品接続のpointerと統合契約は構造化した所有境界を検査する。一般policyの散文は工場の接続と製品正本へのpointerだけを持ち、製品内部の効果や手順を複製しない。この意味境界を任意の散文から機械推測できるとは扱わない。
- 変動する現行値の機械可読な正本は`lib/factory/deployment-contract.mjs`である。`node bin/render-current-docs.mjs --write`が[工場の現行状態](factory-current-state.md)を生成する。
- `make lint-current-docs`はCommonMark/GFM構文木、HTML parser、srcset grammarでreference／nested image／`href`／`src`／`srcset`を読み、code nodeは検査対象から外す。その上で生成drift、未分類文書、current文書への変動値手入力、current local link切れ、未登録archive増減、凍結本文・role・台帳entryの基準commit相対drift、互換stubの改変、構造化した製品pointer／統合契約への内部制御・履歴の逆流を拒否する。archive本文の相対linkは移動前pathを基準に検査し、本文自体を修正しない。
- `node --test tests/docs/current-docs.test.mjs`は冪等生成、drift拒否、closed current集合、reference／HTMLを含むlink閉包、archive inventory、凍結digestとrole、stub digest、製品区分、構造化した文書所有境界、基準commit相対の不変性を検証する。

## CI（[.github/workflows/ci.yml](../.github/workflows/ci.yml)）

- 工場横断のCI契約、責任境界、製品caller、runner登録・repo移転手順は
  [factory-ci runbook](../shared/runbooks/factory-ci.md)を正とする。本書へ複製しない。
- dotagents自身は[工場の現行状態](factory-current-state.md)で`full CI`としたMac、rabbit Linux、Windows nativeの3環境で`make --jobs="$FACTORY_CI_JOBS" ci`を実行する。`FACTORY_CI_JOBS`には各runnerの利用可能な論理CPU数を設定し、独立gateをその上限まで並列実行する。main-server runnerは運用workflow専用で、通常CIと変更分類jobには使わない。`node`・`npm`・`python3`・`shellcheck`・
  `rg`・`codex`のversion確認も同じコマンド列に含める。full jobとMarkdown-only jobはともに
  `npm ci --ignore-scripts`を独立stepで先行する。Markdownだけの変更はLinuxで文書、共通憲法、正典移設、skillの関連gateを実行する。host固有の変更はLinuxの共通検査と該当hostを実行し、共通変更・未分類・CI自身の変更はLinuxを実行し、host固有変更が混ざる場合は該当hostも維持する。3環境の全検査は週次または手動実行で行う。変更分類と最終合否は`scripts/dotagents-ci-plan.mjs`が所有し、選択されたfull jobのskipと分類失敗を最終gateで拒否する。
- npx が `markdownlint-cli2@0.23.0` を都度取得（固定版＝ルール変更でゲートが勝手に赤/緑にならない）。

## 拡張の指針

- shell/docs を足したら glob は自動で拾う（`bin/*.sh`・`docs/**/*.md`）。新しい docs サブディレクトリ（`audit-YYYY-MM/` 等）も対象に入る。
- Node.js scriptは`bin/*.mjs`、`scripts/*.mjs`、`lib/orchestrate/*.mjs`を`node --check`し、Python coreは`lib/orchestrate/*.py`を`py_compile`する。`render-current-docs.mjs`はrepo開発・CI専用であり、`install.sh`は`~/.local/bin`へ配布しない。factory reporterはfake BugHubを使う動的testも通す。
- 別種の lint（yaml・json 等）を足すなら Makefile に `lint-<kind>` を増やし `lint` の依存に足す＝ローカルと CI が同時に追従する。
