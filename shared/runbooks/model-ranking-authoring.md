# 02モデル順位表の書き方とJev確認

所有: dotagents。編集者向け補足資料。Jevへ渡す正本は[02_models.md](02_models.md)だけであり、本書はJevの入力に含めない。順位・モデル諸元・利用枠の閾値は02を正とし、本書に複製しない。

## 語の使い分け

| 語 | 02で表すもの | 書くときの注意 |
|---|---|---|
| モデル | 推論を行うモデル。effortを添えて候補にする | Grok 4.7はモデル、Grok Buildはハーネス。ベンダー名と製品名を混同しない |
| 候補群 | 一つの役割で同じ優先度に置くモデル×effortの集合 | 表の左ほど優先。同格なら同じセルに置き、セル内の記載順を順位にしない |
| ハーネス | モデルを実行する製品・アプリ | Codex、Claude Code、Grok Build、Cursorの固有名で書く。「入口」だけで代用しない |
| 利用枠 | ハーネスの契約で使える残量と、その計測期間 | 「枠」だけで代用しない。Claude Codeの5時間、Codexの週次、Grok Buildの直接、Cursorの利用枠を区別する |

親ハーネスと子のモデル選択は別の判断。親がCodexでも、子の同格候補にClaudeのモデルがあり、優先条件が成立すればClaude Codeを選ぶ。条件文には対象の**モデル・ハーネス・利用枠**を明記する。条件は上から評価し、成立した項目で確定して後続を評価しない。利用枠が尽きて使えない候補は、その項目の成立と扱わない。

## 02を編集するとき

- 世代交代はオーナーが宣言する。宣言を受けたら02の諸元と順位を更新し、下のJev実呼出しで確認する。
- 役割の意味、同格の候補群、モデル×effort、使用可能なハーネスを02内で読めるようにする。Jevが会話の前提を知っているものとして略さない。
- 同じ語は同じ意味で使う。特にモデル名をハーネス名、候補群を利用枠、親の既定を子の優先順位として読める文を作らない。
- 判断の正本は02だけに置く。本書の試験値は過去の観測であり、現行の残量やモデル順位を表さない。
- 02を変えたら、同じ本文を使ったJev実呼出しで読者面を確認する。

## Jev実呼出し（2026-09-23）

公式TypeSafe `POST /v1/systemone`へ`model: jev-latest`を指定し、応答は`jev-1.13.0`だった。02本文を`state`に渡し、各任務・仮定した利用枠・利用可能なモデル×ハーネスを`choice`質問に渡した。質問文にも「同格候補の条件は上から判定し、一つ成立した時点で確定して以降を判定しない」と明記した。認証情報は入力に含めず、子ハーネスの起動も実残量の取得もしていない。

| 仮定した任務と利用枠 | 期待する選択 | 用語・停止条件を明記した02でのJev選択 | 選択確率 / confidence |
|---|---|---|---|
| 仕様確定済みの実装。Claude Codeの5時間利用枠を使える | Claude Code / Opus 5.5×medium | 一致 | 0.78 / 0.68 |
| 実ファイルを読む反証。Codexの週次使用率は均等ペースの1.3倍、Grok Buildの直接利用枠を使える | Grok Build / Grok 4.7×high | 一致 | 0.88 / 0.83 |
| 同じ反証。Grok Buildの直接利用枠は枯渇、Cursorの利用枠を使える | Cursor / Grok 4.7×high | 一致 | 0.49 / 0.24 |

先行試行では、三つの条件を一度に読ませて単一の選択を求め、最初の実装任務にCodex / Solが選ばれた（選択確率0.64）。優先語だけを強めても同じ誤選択だった（0.71）。そこでオーナーが「一つ成立したら後続を判定しない」と明確化し、候補群・ハーネス・利用枠の意味を02へ書いた。上表の3件はその後の一回ずつの結果である。試行間で02と質問文の両方を変えており、改善の原因を一方だけへ帰属できない。役割だけをJevへ問う別の実呼出しでは、同じ任務を「実装」（confidence 0.99）と「反証」（1.00）に分類した。

この3件は**仮定した利用枠での読解確認**であり、実際のハーネス残量や繰り返しの安定性は示さない。特にCursorの選択は確率0.49・confidence 0.24なので、一回の一致を安定動作と解釈しない。以前の推薦CLIで、取得不能の利用枠観測をJevへ渡すと`none`になった実例は[修理記録](../../evidence/harness-model-effort-recommender/hmer-005-live-fix.md)にある。利用枠の未観測を「枯渇」として入力しない。

次の編集後も、同じ3条件と、変更した役割の代表任務を正規のTypeSafe APIへ投げる。Jevの選択肢には02で実際に使えるモデル×ハーネスだけを置き、期待した条件で停止したか、選択確率とconfidenceまで記録する。
